# 체결 · 인프라 (Execution & Infrastructure)

## 주문 유형 (Order Types)
- **시장가 주문 (Market Order)**: 즉시 체결, 가격은 불확실(스프레드·슬리피지 부담)
- **지정가 주문 (Limit Order)**: 가격은 확실, 체결은 불확실(원하는 가격에 안 닿으면 미체결)
- **손절 주문 (Stop Order)**: 특정 가격에 닿으면 발동

## 부분체결 (Partial Fill)
주문 수량이 한 번에 다 채워지지 않고 일부만 체결되는 것. 시스템이 이 상태를 추적·처리해야 한다.

## 멱등성 (Idempotency)
같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같게 만드는 성질. 네트워크 재시도로 **주문이 중복 발사되는 사고**를 막기 위해 client order id 등으로 보장한다.

## 주문 상태기계 (Order State Machine)
주문의 생애주기(접수→부분체결→체결→취소/거부)를 상태로 추적하고, 증권사 기록과 대조(reconciliation)하는 구조.

## 장애 안전 (Fail-safe)
연결 끊김·이상 데이터·API 다운 등 비정상 상황에서 **기본 동작이 "매매 안 함"**이 되도록 설계하는 원칙.

## 킬 스위치 (Kill Switch)
일일 최대손실 등 한도에 도달하면 매매를 강제 중단하는 안전장치.

## HFT (High-Frequency Trading, 초단타매매)
마이크로초~나노초 단위 속도로 경쟁하는 매매. **속도 자체가 엣지**다. 승자독식이라 2등은 이익이 아니라 음의 선택(adverse selection)을 당한다.

## 코로케이션 (Co-location)
거래소 매칭엔진과 **같은 데이터센터 안에 서버를 두는 것**. 빛의 속도(거리) 때문에 지연을 줄이려는 HFT의 필수 요소. 개인은 접근 불가.

## 레이턴시 (Latency)
주문/데이터가 오가는 지연 시간. HFT는 수~수십 µs, 개인 브로커 API는 수십~수백 ms로 1,000~100,000배 차이.

## 음의 선택 / 역선택 (Adverse Selection)
느린 참가자가 빠른 돈이 "불리하다"고 버린 주문만 체결당해, 체계적으로 나쁜 가격에만 거래되는 현상.

## 페이퍼 트레이딩 (Paper Trading) / 모의투자
실제 돈 없이 가상 계좌로 전략을 실시간 검증하는 것. 백테스트와 실거래의 괴리를 줄이는 중간 단계. KIS는 모의투자 계좌를 제공한다.
